# Phase 04 Plan 01: Discussion — Отзывы, промокоды, продвижение

## Context from Previous Phases

- Phase 02: Booking with overlap prevention, chat
- Phase 03: Mock payments for confirm mode

## Requirements

### Reviews (Отзывы)

**Key constraints:**
- Only clients who completed a visit can leave reviews
- Reviews include rating (1-5) and text comment
- Reviews are linked to booking (one review per completed booking)
- Partner can respond to reviews
- Admin can moderate/delete reviews

**Questions:**
1. Should reviews be moderated before publication? (recommend: yes, admin approval)
2. Can partners respond publicly or only internally? (recommend: public response)
3. What happens if booking is cancelled? (no review allowed)

### Promo Codes (Промокоды)

**Features:**
- Alphanumeric code (e.g., "SUMMER2024")
- Discount types: percentage (10%), fixed amount (500 RUB), free service
- Usage limits: total uses, per-user limits
- Validity period: start/end dates
- Applicable to: specific venues, all venues, specific services
- Minimum booking amount requirement

**Questions:**
1. Should promo codes apply to services or only venue booking? (recommend: both)
2. Can multiple promo codes be used per booking? (recommend: no, one per booking)
3. Auto-apply best promo or manual entry? (recommend: manual entry)

### Marketing/Promotion (Продвижение)

**Features:**
- Venue rating calculation (average from reviews)
- Featured venues (admin-curated)
- Search ranking boost for promoted venues
- Venue statistics (views, bookings, revenue)

**Questions:**
1. Should there be paid promotion (boost) for partners? (recommend: future phase)
2. What metrics for venue statistics? (recommend: bookings, revenue, rating)

## Recommended Approach

### 1. Reviews System

**Schema:**
```
model Review {
  id        String   @id @default(cuid())
  bookingId String   @unique
  rating    Int      (1-5)
  comment   String
  status    ReviewStatus (PENDING/APPROVED/REJECTED)
  response  String?  (partner response)
  createdAt DateTime
}
```

**API:**
- POST /api/v1/bookings/[id]/review — create review (client, after COMPLETED)
- POST /api/v1/reviews/[id]/respond — partner response
- PATCH /api/v1/admin/reviews/[id] — admin moderate
- GET /api/v1/venues/[slug]/reviews — list venue reviews

### 2. Promo Codes

**Schema:**
```
model PromoCode {
  code           String   @id
  discountType   DiscountType (PERCENTAGE/FIXED)
  discountValue  Int      (10 = 10%, or 500 = 500 RUB)
  minAmount      Int?     (minimum booking amount in kopecks)
  maxUses        Int?     (total usage limit)
  maxUsesPerUser Int?     (per-user limit)
  validFrom      DateTime
  validUntil     DateTime
  applicableVenues String[] (venue IDs, empty = all)
  active         Boolean
}

model PromoCodeUsage {
  id          String   @id
  promoCodeId String
  userId      String
  bookingId   String   @unique
  discountApplied Int
  createdAt   DateTime
}
```

**API:**
- POST /api/v1/promocodes/validate — check code validity
- POST /api/v1/bookings/[id]/apply-promo — apply to booking
- GET /api/v1/promocodes — list active codes (admin/partner)

### 3. Marketing/Rating

**Features:**
- Calculate venue rating from approved reviews
- Track venue statistics (bookings count, revenue)
- Admin can mark venues as "featured"

**API:**
- GET /api/v1/venues/[slug]/rating — venue rating and review count
- GET /api/v1/venues/[slug]/stats — venue statistics (partner only)
- PATCH /api/v1/admin/venues/[id]/featured — toggle featured status
