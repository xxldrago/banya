# Phase 03 Plan 01: Discussion — Платежи и подтверждение

## Context from Phase 02

Phase 02 implemented booking with three modes:
- **instant**: MVP mode, no payment required, booking becomes CONFIRMED immediately
- **confirm**: Requires payment/confirmation, booking starts as PENDING
- **pay_on_site**: Pay at venue, booking CONFIRMED but payment pending

## Questions for Phase 03

### Payment Integration

1. **Which payment provider to integrate?**
   - CloudPayments (popular in Russia)
   - YooKassa (Yandex.Kassa)
   - Tinkoff Kassa
   - Stripe (not available in Russia)
   - Mock/test payment for MVP?

2. **Payment flow for "confirm" mode:**
   - User creates booking → PENDING
   - System generates payment link/token
   - User completes payment
   - Webhook confirms payment → booking becomes CONFIRMED
   - Payment timeout (e.g., 15 min) → booking EXPIRED

3. **What payment data to store?**
   - Payment ID (from provider)
   - Amount
   - Status (pending/success/failed/refunded)
   - Payment method
   - Timestamps

### Schema Extensions

4. **New tables needed:**
   - `Payment` table linked to `Booking`
   - Fields: id, bookingId, provider, providerPaymentId, amount, status, metadata, createdAt, updatedAt

5. **Booking status updates:**
   - PENDING → CONFIRMED (on payment success)
   - PENDING → EXPIRED (on timeout)
   - CONFIRMED → REFUNDED (on cancellation with refund)

### API Endpoints

6. **New endpoints:**
   - POST /api/v1/bookings/[id]/pay — initiate payment
   - GET /api/v1/bookings/[id]/payment-status — check status
   - POST /api/v1/payments/webhook — payment provider webhook
   - POST /api/v1/bookings/[id]/refund — refund payment

### Business Logic

7. **Payment timeout handling:**
   - Cron job to expire unpaid bookings?
   - Or check on-demand when user queries status?

8. **Refund policy:**
   - Full refund if cancelled X hours before?
   - Partial refund?
   - No refund?

## Recommended Approach for MVP

Given the complexity, I recommend:

1. **Start with mock payment service** — simulate payment flow without real provider
2. **Add Payment table** — track payment intent and status
3. **Implement webhook endpoint** — prepare for real provider integration
4. **Add payment timeout** — 15-minute window for confirm mode
5. **Create payment initiation endpoint** — returns mock payment URL
