       - Validate input with CreateBookingSchema
       - Start prisma.$transaction(async (tx) => { ... }, { isolationLevel: "Serializable" }) (D-02)
       - Inside transaction:
         a. Lock venue row: await tx.$queryRawUnsafe(`SELECT id FROM "Venue" WHERE id = $1 FOR UPDATE`, input.venueId) (D-02)

              - If allowBackToBack=true: conflict if existing.startsAt < input.endsAt AND existing.endsAt > input.startsAt (strict)
              - If allowBackToBack=false: conflict if existing.startsAt <= input.endsAt AND existing.endsAt >= input.startsAt (touching counts)
            - If conflict found: throw new HttpError("SLOT_UNAVAILABLE", "Time slot is not available", 409)
         d. Create booking: tx.booking.create({ data: { venueId, userId, startsAt, endsAt, status: input.bookingMode === "instant" ? "CONFIRMED" : "PENDING", bookingMode: input.bookingMode, allowBackToBack: input.allowBackToBack } })
         e. If serviceIds provided: for each serviceId, fetch Service, create BookingService with priceAtBooking = service.defaultPrice (D-07)
         f. If status === "CONFIRMED": call createConversationForBooking(tx, booking) (D-08)
         g. Return booking with services and conversation

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → API | Untrusted input (booking dates, service IDs) |
| API → Database | Trusted but must prevent race conditions |
| WebSocket client → WS server | JWT auth required, participant membership check |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | Booking creation | high | mitigate | SELECT FOR UPDATE + Serializable isolation prevents concurrent double-booking |
| T-02-02 | Elevation | Chat access | high | mitigate | Participant membership check in chat service + JWT verify on WS connect |
| T-02-03 | Tampering | Price snapshot | medium | mitigate | priceAtBooking copied at creation, immutable after |
| T-02-04 | Spoofing | WebSocket connection | high | mitigate | JWT token verification in WS handshake, short-lived access tokens |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | package-legitimacy gate + blocking human checkpoint for ws package |
</threat_model>
