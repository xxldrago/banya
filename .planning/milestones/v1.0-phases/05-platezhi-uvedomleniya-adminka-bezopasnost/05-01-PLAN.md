# Phase 05 Plan 01: Discussion — Платежи, уведомления, админка, безопасность

## Requirements

### Notifications (Уведомления)

**Email notifications:**
- Booking confirmation (instant mode)
- Payment confirmation (confirm mode)
- Booking reminder (24h before)
- Cancellation notification
- Review reminder (after visit)

**SMS notifications (optional):**
- Booking confirmation
- Reminder

**Implementation:**
- Use nodemailer for email
- Template system (handlebars or similar)
- Queue system for async sending

**Questions:**
1. Which email provider? (recommend: SMTP via SendGrid or SES)
2. Should notifications be opt-in or opt-out? (recommend: opt-out)
3. Do we need SMS? (recommend: optional, via Twilio or similar)

### Admin Dashboard (Админка)

**Features:**
- Dashboard with stats (bookings, revenue, users)
- Venue management (approve/reject)
- User management (role changes, block)
- Booking management (view, cancel, refund)
- Review moderation
- Promo code management
- System settings

**Questions:**
1. Should admin dashboard be a separate app or integrated? (recommend: integrated Next.js app)
2. Which admin roles? (recommend: SUPER_ADMIN, MODERATOR, FINANCE)
3. Real-time stats? (recommend: yes, via WebSocket)

### Security (Безопасность)

**Areas:**
- Rate limiting on API endpoints
- CSRF protection
- Input validation (already done via Zod)
- SQL injection protection (already done via Prisma)
- JWT token security (already implemented)
- Password security (argon2, already done)
- File upload security
- Environment variables protection

**Questions:**
1. Rate limiting strategy? (recommend: per-IP + per-user)
2. Should we add 2FA for admin? (recommend: future phase)
3. File upload restrictions? (recommend: images only, max 5MB)

## Recommended Approach

### 1. Notifications

**Schema additions:**
```
model Notification {
  id        String   @id @default(cuid())
  userId    String
  type      String   // booking_confirmed, payment_confirmed, etc.
  channel   String   // email, sms
  subject   String
  body      String
  status    String   // pending, sent, failed
  sentAt    DateTime?
  createdAt DateTime
}
```

**API:**
- POST /api/v1/notifications — send notification (admin/internal)
- GET /api/v1/notifications — list user notifications

### 2. Admin Dashboard

**Pages:**
- /admin — Dashboard
- /admin/venues — Venue management
- /admin/users — User management
- /admin/bookings — Booking management
- /admin/reviews — Review moderation
- /admin/promos — Promo code management
- /admin/settings — System settings

**API:**
- GET /api/v1/admin/stats — Dashboard statistics
- PATCH /api/v1/admin/venues/[id] — Update venue
- PATCH /api/v1/admin/users/[id] — Update user
- DELETE /api/v1/admin/bookings/[id] — Delete booking
- PATCH /api/v1/admin/reviews/[id] — Moderate review
- PATCH /api/v1/admin/promos/[id] — Update promo

### 3. Security

**Rate limiting:**
- Redis-based rate limiting
- Per-endpoint limits
- Per-IP and per-user

**Additional:**
- Helmet.js for security headers
- CORS configuration
- Request logging
